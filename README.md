# Анализ свободных слотов врачей на НаПоправку

Дашборд для анализа врачей на `napopravku.ru`.

## Для коллег

После публикации на Render коллеги будут открывать обычную ссылку в браузере, вставлять ссылку на страницу врачей/клиники и нажимать `Анализировать`. Устанавливать GitHub, Codex, Node.js или другие программы им не нужно.

## Как запустить

1. Откройте файл `Запустить анализатор.command`.
2. В браузере откроется адрес `http://localhost:4355`.
3. Вставьте ссылку на страницу клиники, врачей или специальности, например:
   `https://napopravku.ru/kirov/clinics/sovermed/`
   или
   `https://napopravku.ru/kirov/clinics/sovermed/vrachi/#doctors`
   или
   `https://napopravku.ru/kirov/doctors/stomatolog-terapevt/`
4. Нажмите `Анализировать`.

Во время анализа программа запускает свой фоновый браузер Playwright. Вы видите только дашборд и итоговый отчет.
Даты `сегодня` и `завтра` считаются по городу из ссылки НаПоправку, а не по времени сервера Render.

## Как будет опубликовано

Проект рассчитан на связку:

- GitHub — хранит код;
- Render — запускает сайт и сервер анализа;
- Docker — делает запуск одинаковым и предсказуемым в облаке.

В Render можно использовать `render.yaml` из этого проекта. Сервис запускается как Docker Web Service.

Для платного Render целевые настройки:

- `MAX_PARALLEL_ANALYSES=3` — до 3 анализов одновременно;
- `ANALYSIS_TIMEOUT_MS=900000` — один анализ не висит дольше 15 минут;
- 4-й и следующие анализы становятся в очередь и стартуют автоматически.

## Что показывает

- прогресс анализа в процентах;
- текущий этап: загрузка страницы, подгрузка врачей, анализ слотов, готово;
- врачей, у которых больше 3 свободных слотов на сегодня;
- врачей, у которых больше 3 свободных слотов на завтра;
- общий список врачей, у которых найдены слоты на эти даты;
- количество загруженных карточек;
- сколько раз была нажата кнопка `Показать ещё`.
- кнопку `Скачать Excel`;
- редактируемый текст коммерческого предложения с кнопкой копирования.

Инструмент автоматически прокручивает страницу вниз и нажимает `Показать ещё`, пока кнопка доступна.
Если страница уже отдала заявленное количество врачей, анализатор прекращает подгрузку и сразу переходит к слотам.
Перед чтением слотов анализатор прокручивает каждую карточку врача в видимую область. Это важно для страниц, где НаПоправку лениво дорисовывает кнопки времени только у видимых карточек.

## Параллельная работа

На сервере каждый запуск анализа создается как отдельная задача со своим статусом, прогрессом и результатом. До 3 менеджеров могут запускать анализы одновременно. Если одновременно запускается 4-й анализ, он становится в очередь и автоматически начнется, когда один из первых трех завершится. 5-й, 6-й и следующие анализы встают в очередь следом за ним и запускаются по порядку.

Количество тяжелых фоновых браузеров регулируется переменной `MAX_PARALLEL_ANALYSES`; безопасное значение для Render Standard после нагрузочной проверки — `3`.

Если анализ завис, сервер останавливает его по тайм-ауту и освобождает место для следующей задачи.

Чтобы параллельные анализы не запускали отдельный браузер на каждую задачу, сервер использует один общий Chromium и отдельный контекст для каждой задачи. В фоновом браузере также отключена загрузка картинок, шрифтов и медиа — для анализа нужны текст и DOM страницы, а не тяжелые визуальные ресурсы. Стили не блокируются, потому что они помогают корректно определить видимость кнопок и слотов.

## Проверка для разработки

```bash
npm test
node --check server.js
node --check public/app.js
```

Сейчас основные проверки покрывают очередь задач, тайм-аут зависшего анализа, настройки Chromium, ускоренные ожидания и проверку ссылок НаПоправку.
Также есть проверки часовых поясов городов и защиты от ситуации, когда врач найден, но слоты не считались из-за невидимой карточки.

## Если что-то пошло не так

Если программа показывает старую ошибку или ведет себя странно:

1. Закройте старое окно Терминала с анализатором.
2. Снова откройте `Запустить анализатор.command`.
3. Откройте `http://localhost:4355`.
